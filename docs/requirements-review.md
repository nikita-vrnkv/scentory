# Сверка с заданием преподавателя

Основание: предоставленный пользователем текст задания «Создайте работающего бота
в Telegram или MAX, через которого клиент выбирает товар или услугу и оформляет покупку».
Проверены файлы текущего проекта. Пользователь сообщил, что бот работает;
это сообщение не заменяет отдельный протокол демонстрации с двумя пользователями.

## Вывод

Обязательный функциональный объём реализован в коде и покрыт автоматическими
тестами. Репозиторий: [nikita-vrnkv/scentory](https://github.com/nikita-vrnkv/scentory).
Для сдачи дополнительно нужны реальные материалы демонстрации, перечисленные ниже.

## Функции и подтверждение в коде

| Требование | Реализация |
| --- | --- |
| Работающий код и БД, а не макет | `scentory/__main__.py`, обработчики aiogram, файловая SQLite через aiosqlite |
| Название, минимум 5 позиций, описания и цены | Scentory, 6 вымышленных ароматов в `database/seed.py`, загрузка из `products` |
| `/start`, меню, карточки, кнопки и возврат | `handlers/common.py`, `catalog.py`, `keyboards.py` |
| Корзина пользователя, количество, удаление, итог | `database/repository.py`, `handlers/cart.py`; владелец из Telegram ID |
| Запрет пустой корзины и неверного количества | Проверки репозитория и оформления, ограничения `schema.sql` |
| Имя/псевдоним, проверка состава и суммы | `handlers/checkout.py`, `database/orders.py` |
| Самовывоз, расчёт при получении, без фиктивной оплаты | Проверка и детали заказа показывают условия; статуса «Оплачено» нет |
| Уникальный номер, статус, сохранение после перезапуска | `orders.id` AUTOINCREMENT, файловая SQLite; начальный статус «Новый» |
| Исторические цена и название | Снимки в `order_items`, отдельные от текущего каталога |
| Атомарное создание и очистка корзины | `confirm_checkout`: BEGIN IMMEDIATE, запись всех частей, COMMIT / ROLLBACK |
| Повторное подтверждение без дубликата | UUID оформления, UNIQUE ключ заказа, возврат существующего заказа с проверкой владельца |
| Только свои заказы | `get_order` и `list_orders` ограничивают SQL по Telegram ID владельца |
| Менеджер по ID: новые заказы и статусы | `ADMIN_IDS`, `handlers/admin.py`, повторная проверка прав в `database/admin.py` |
| Пустой каталог, недоступные товары, старые кнопки, ошибки | Обработчики каталога, корзины, оформления, заказов и менеджера |
| Секреты вне кода | Настройки через `.env`, шаблон `.env.example`, исключения в `.gitignore`; настоящий `.env` не проверялся и не читался |
| Зависимости, запуск, начальное наполнение | `requirements.txt`, команды Windows/macOS/Linux в README, идемпотентная инициализация |
| Четыре ответа, схема сценария, роли, технологии, БД и ограничения | README содержит все разделы |

## Материалы для сдачи

1. Предоставить ссылку на репозиторий и версию `v1.0-stage1`.
2. Снять реальные скриншоты или короткое видео полного пути покупки и заказа после
   перезапуска. Не показывать секреты и настоящие персональные данные.
3. Выполнить демонстрационные пункты преподавателя с двумя учебными пользователями
   и менеджером; заполнить [ручной протокол](manual-testing.md).
4. Приложить основной запрос к ИИ и 2–3 реальных уточнения из переписки.
   Выдержки собраны в [ai-usage.md](ai-usage.md); полный запрос доступен в исходном чате.
5. Самостоятельно описать, что было проверено, какие ошибки обнаружены и исправлены.
   Ответы на защите должны опираться на фактически выполненные действия.

Протокол остаётся шаблоном: автоматические тесты не заменяют демонстрацию Telegram.
