# Сверка с заданием преподавателя

Основание: предоставленный пользователем текст задания «Создайте работающего бота
в Telegram или MAX, через которого клиент выбирает товар или услугу и оформляет покупку».
Проверены файлы текущего проекта. Пользователь сообщил, что бот работает;
это сообщение не заменяет отдельный протокол демонстрации с двумя пользователями.

## Вывод

Обязательные функции реализованы. Несоответствий обязательному функциональному
объёму при проверке кода не выявлено. Комплект материалов для сдачи пока неполный:
в проекте не найдены ссылка на опубликованный репозиторий, реальные скриншоты/видео,
заполненный ручной протокол и отдельное описание использования ИИ.

## Функции и подтверждение в коде

| Требование | Реализация |
| --- | --- |
| Работающий код и БД, а не макет | `scentory/__main__.py`, обработчики aiogram, файловая SQLite через aiosqlite |
| Название, минимум 5 позиций, описания и цены | Scentory, 6 вымышленных ароматов в `database/seed.py`, загрузка из `products` |
| `/start`, меню, карточки, кнопки и возврат | `handlers/common.py`, `catalog.py`, `keyboards.py` |
| Корзина пользователя, количество, удаление, итог | `database/repository.py`, `handlers/cart.py`; владелец из Telegram ID |
| Запрет пустой корзины и неверного количества | Проверки репозитория и оформления, ограничения `schema.sql` |
| Имя/псевдоним, проверка состава и суммы | `handlers/checkout.py`, `database/orders.py` |
| Самовывоз, расчёт при получении, без фиктивной оплаты | Проверка и детали заказа показывают условия; статуса «Оплачено» нет |
| Уникальный номер, статус, сохранение после перезапуска | `orders.id` AUTOINCREMENT, файловая SQLite; начальный статус «Новый» |
| Исторические цена и название | Снимки в `order_items`, отдельные от текущего каталога |
| Атомарное создание и очистка корзины | `confirm_checkout`: BEGIN IMMEDIATE, запись всех частей, COMMIT / ROLLBACK |
| Повторное подтверждение без дубликата | UUID оформления, UNIQUE ключ заказа, возврат существующего заказа с проверкой владельца |
| Только свои заказы | `get_order` и `list_orders` ограничивают SQL по Telegram ID владельца |
| Менеджер по ID: новые заказы и статусы | `ADMIN_IDS`, `handlers/admin.py`, повторная проверка прав в `database/admin.py` |
| Пустой каталог, недоступные товары, старые кнопки, ошибки | Обработчики каталога, корзины, оформления, заказов и менеджера |
| Секреты вне кода | Настройки через `.env`, шаблон `.env.example`, исключения в `.gitignore`; настоящий `.env` не проверялся и не читался |
| Зависимости, запуск, начальное наполнение | `requirements.txt`, команды Windows/macOS/Linux в README, идемпотентная инициализация |
| Четыре ответа, схема сценария, роли, технологии, БД и ограничения | README содержит все разделы |

В исходных ответах 2 и 4 README сохранилась ранняя формулировка о телефоне и
контактных данных. Она не изменялась по просьбе пользователя. Сразу после четырёх
ответов дано явное уточнение: требуется только имя/псевдоним; телефон и адрес не
собираются. Это соответствует выбранному самовывозу и заданию преподавателя.

## Что ещё нужно для сдачи

1. Опубликовать исходники в репозитории и предоставить ссылку. В текущем каталоге
   не обнаружена папка `.git`; публикация вне проекта не проверялась. Не включать
   `.env`, виртуальное окружение и локальную БД.
2. Снять реальные скриншоты или короткое видео полного пути покупки и заказа
   после перезапуска. Не показывать секреты и настоящие персональные данные.
3. Выполнить именно шесть демонстрационных пунктов преподавателя с двумя учебными
   пользователями и менеджером. Заполнить фактические результаты в
   `docs/manual-testing.md`: шаблон уже есть, результаты в нём пустые.
4. Подготовить основной запрос к ИИ и 2–3 реальных уточнения из переписки.
   Отдельно своими словами описать, что студент проверил и изменил самостоятельно.
   Ни результаты, ни выполненную студентом работу не следует выдумывать.
5. На защите показать запись вновь созданного заказа в SQLite и объяснить
   расчёт суммы, разделение пользователей, хранение токена и сохранность после
   перезапуска. В README есть раздел «Что объяснить на защите».

При этой сверке повторно запущен полный набор: **66 тестов, OK** на Windows /
Python 3.13.2. Тесты использовали отдельные временные базы и подмену Telegram.
Автоматические проверки не заменяют эти материалы. Проверка установки на чистом
компьютере и запуск на macOS/Linux отдельно не выполнялись.

## Очистка учебных данных

По запросу пользователя в `data/scentory.sqlite3` одной транзакцией удалены:
3 заказа, 4 позиции заказов и 2 пользователя. Корзины и черновики уже были пусты;
после операции все пять таблиц пользовательских данных содержали 0 строк.
Все 6 товаров сохранены без изменений. `foreign_key_check` не выявил нарушений,
`integrity_check` вернул `ok`.

Счётчик номеров заказов сохранён: старые кнопки Telegram не должны указывать на
новые заказы с повторно использованными номерами. Настройки менеджера не менялись.
Сообщения в Telegram не удалялись; очистка относится к данным проекта. После
нового `/start` пользователь снова будет зарегистрирован.
