# Scentory

Учебный Telegram-магазин парфюмерии: [@ScentoryBot](https://t.me/ScentoryBot).
Покупатель выбирает аромат и оформляет самовывоз, менеджер обрабатывает заказ.
Расчёт — при получении; онлайн-оплаты нет.

## Предметная область

1. **Кто покупатель и что он хочет получить?** Человек, который выбирает парфюмерию
   для себя или в подарок: изучает ароматы, характеристики и цены и оформляет заказ в боте.
2. **Что он выбирает и какие сведения нужны?** Один или несколько ароматов и их
   количество. Для заказа достаточно имени или псевдонима; телефон и адрес не нужны.
   Перед подтверждением покупатель проверяет состав и сумму.
3. **Что происходит после подтверждения?** Заказ получает номер и статус «Новый».
   Менеджер видит его и меняет статус: «В обработке», «Готов к выдаче», «Выдан»,
   «Отменён». Покупатель видит актуальный статус при открытии заказа.
4. **Когда заказ оформлен?** После нажатия «Подтвердить заказ» и успешного сохранения
   заказа и его позиций в SQLite. Бот показывает номер; корзина очищается.

## Возможности и сценарий

**Покупатель:** каталог из шести вымышленных ароматов, карточки товаров, личная
корзина, изменение количества и удаление позиций, проверка и подтверждение заказа,
список и детали собственных заказов. Пустую корзину оформить нельзя.

**Менеджер:** новые и все заказы, детали, изменение статуса через кнопки.
Доступ проверяется по числовому Telegram ID в обработчиках и слое базы данных.
Команды: `/start` — меню, `/myid` — свой ID, `/admin` — управление заказами.

```text
/start → Каталог → Карточка → Добавить в корзину → Корзина
       → Имя или псевдоним → Проверка заказа → Подтверждение
       → Номер заказа → Мои заказы → Детали и статус
```

До подтверждения можно вернуться в корзину, изменить количество или удалить товар.
Если после проверки изменились товары или цены, потребуется проверить заказ заново.
Повторное, в том числе одновременное, подтверждение возвращает прежний номер.

## Технологии и структура

Python 3.11+, aiogram 3, SQLite, aiosqlite, python-dotenv.
Версии рабочих зависимостей закреплены в `requirements.txt`.
Тесты используют стандартный `unittest`; для проверки стиля применяется Ruff.

```text
scentory/
  __main__.py       # запуск и регистрация обработчиков
  config.py         # настройки из окружения и локального .env
  keyboards.py      # общие inline-клавиатуры
  formatting.py     # цены и представление заказа
  handlers/         # меню, каталог, корзина, оформление, заказы, менеджер
  database/         # соединения, схема, начальный каталог, операции с данными
tests/              # тесты с временной SQLite и имитацией Telegram API
docs/               # ручные проверки и материалы к сдаче
.env.example        # настройки без секретов
requirements.txt    # зависимости для запуска
requirements-dev.txt # дополнительные средства разработки
pyproject.toml      # правила Ruff
```

## База данных

| Таблица | Назначение |
| --- | --- |
| `users` | Локальный ID, уникальный Telegram ID, платформа и основные сведения |
| `products` | Название, описание, объём, цена, доступность и ключ начального товара |
| `cart_items` | Товар и положительное количество в корзине конкретного пользователя |
| `checkout_drafts` | Сохранённая операция оформления и проверенный состав корзины |
| `orders` | Номер, покупатель, псевдоним, итог, получение, расчёт, статус, дата, уникальный ключ операции |
| `order_items` | Товары заказа с названием, ценой и количеством на момент покупки |

Связи: пользователь → корзина, черновик и заказы; заказ → позиции; позиции → товар.
Внешние ключи и ограничения защищают связи, количество и уникальность.
Деньги хранятся в целых копейках. Цены и суммы берутся из БД, а не из кнопок Telegram.
Создание заказа, запись позиций и очистка корзины выполняются одной транзакцией.
Историческая цена не меняется при изменении каталога. Корзины, черновики и заказы
сохраняются после перезапуска при использовании того же файла SQLite.

## Установка и запуск

Нужны Git, Python 3.11 или новее и доступ к Telegram через интернет.
Команды выполняются из корня клонированного проекта.

```text
git clone https://github.com/nikita-vrnkv/scentory.git
cd scentory
```

**Windows PowerShell** (активация окружения не требуется):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Убедитесь, что выбранный командой `py -3` Python имеет версию 3.11+.

**macOS / Linux:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
[ -f .env ] || cp .env.example .env
```

Откройте созданный `.env` в текстовом редакторе и заполните:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего бота из BotFather, только в локальном файле |
| `ADMIN_IDS` | Числовые Telegram ID менеджеров через запятую; пусто — менеджеров нет |
| `DATABASE_PATH` | По умолчанию `data/scentory.sqlite3`; относительный путь считается от корня проекта |

Для существующего Scentory новый бот не нужен. Для независимой копии используйте
собственного бота. Не публикуйте `.env`, токен или рабочую базу. Переменные окружения
процесса имеют приоритет над `.env`.

Запуск в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m scentory
```

Запуск в macOS / Linux:

```bash
.venv/bin/python -m scentory
```

База, таблицы и шесть товаров создаются автоматически. Повторный запуск не дублирует
каталог. Отдельная команда инициализации не нужна. Остановка — `Ctrl+C`.
Запускайте только один polling-процесс для одного токена.

**Настройка менеджера:** отправьте боту `/myid`, внесите полученный ID в `ADMIN_IDS`
локального `.env` и перезапустите программу. После `/start` появится кнопка управления;
также доступна команда `/admin`. Username не даёт прав менеджера.

## Проверки и сдача

Автотесты не требуют токена и не используют рабочую базу или настоящий `.env`.
Они проверяют каталог, корзину, суммы, транзакции и откат ошибок, повторное подтверждение,
сохранение данных, доступ пользователей и менеджера, обработчики и запуск приложения.

```powershell
# Windows PowerShell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\ruff.exe check scentory tests
.\.venv\Scripts\ruff.exe format --check scentory tests
```

```bash
# macOS / Linux
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/ruff check scentory tests
.venv/bin/ruff format --check scentory tests
```

Реальный интерфейс проверьте с двумя учебными пользователями и менеджером по
[шаблону ручного протокола](docs/manual-testing.md). Используйте вымышленные псевдонимы.
[Сверка с заданием](docs/requirements-review.md) перечисляет материалы к сдаче;
[история использования ИИ](docs/ai-usage.md) содержит реальные выдержки из переписки.
Результаты ручных проверок и собственный комментарий студент заполняет самостоятельно.

## Ограничения

Бот работает в личных чатах, пока запущена программа с доступом к интернету.
Ассортимент учебный; редактора каталога и учёта складских остатков нет.
Количество ограничено диапазоном 1–999 единиц на позицию.
Получение — самовывоз из учебного пункта Scentory, расчёт — при получении.
Доставки, онлайн-оплаты и Mini App нет. Изменение статуса видно при повторном открытии
заказа; отдельное уведомление покупателю не отправляется.
